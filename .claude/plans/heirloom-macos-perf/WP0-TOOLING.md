# WP0 — Build, install, logging, profiling harness

Read `PLAN.md` first (global rules). Fixes R0 and R12, and gives WP7 a repeatable perf harness. Besides the files in the PLAN ownership table, you may add the one smoke log line in `MacAppState.swift` (step 2).

## Context
- `Makefile` (repo root):
  - `build-macos` runs `xcodebuild … build` with **no `-configuration`**, so it builds Debug.
  - `install-macos` copies the first `Heirloom-macOS.app` that `find` returns, which may be Debug or Release.
  - The installed app currently contains `Heirloom-macOS.debug.dylib` and `__preview.dylib`.
- The Xcode project is generated by **xcodegen** from `native-apple/project.yml`; the pbxproj is derived.
  Change build settings in `project.yml` and run `make xcodegen`. Never hand-edit the pbxproj.
- `DEVELOPMENT_TEAM ?= 599Z443923` is exported by the Makefile, and `project.yml` reads
  `${DEVELOPMENT_TEAM}`. Keep it.
- Zero logging exists in the app and PhotosCore.

## Steps
1. **Release install**
   - Add `CONFIGURATION ?= Release` to the Makefile.
   - Pass `-configuration $(CONFIGURATION)` in `build-macos`.
   - In `install-macos`, copy exactly `$(DERIVED_DATA)/Build/Products/$(CONFIGURATION)/Heirloom-macOS.app`,
     and fail if it's missing.
   - Quit a running instance first: `osascript -e 'tell application id "com.immich.heirloom.macos" to quit'`
     ignoring errors, then `pkill -x Heirloom-macOS` after 3 s if it's still running.
   - Add `build-macos-debug` for developers. Update `make help`.
   - In `project.yml`, for the macOS app target's **Release** config, make sure
     `ENABLE_DEBUG_DYLIB: NO`, `SWIFT_OPTIMIZATION_LEVEL: -O`, `SWIFT_COMPILATION_MODE: wholemodule` and
     `ENABLE_PREVIEWS: NO` are set. Leave Debug alone.
   - Verify: after `make install-macos`, `ls /Applications/Heirloom-macOS.app/Contents/MacOS/` shows only
     `Heirloom-macOS` (plus any required non-debug helpers), and
     `codesign -dv /Applications/Heirloom-macOS.app 2>&1 | grep TeamIdentifier` prints `599Z443923`.
2. **Logging**
   - Add `PhotosCore/Sources/CoreModel/Log.swift`: `public enum HeirloomLog` with static `os.Logger`s,
     subsystem `com.immich.heirloom`, categories `timeline`, `media`, `sync`, `store`, `ui`.
   - Add `Apps/macOS/Sources/HeirloomLog.swift` re-exporting app categories if needed. If CoreModel is
     visible to the app, re-exporting is unnecessary: say so in the report and skip this file.
   - Add `OSSignposter` helpers, `HeirloomSignpost.interval(_ name: StaticString, _ body:)`, both sync and
     async variants, with signpost names: `GridLoad`, `SnapshotBuild`, `LayoutPrepare`, `ThumbnailFetch`,
     `ThumbnailDecode`, `ViewerOpen`.
   - Other WPs will call these. You only add the API plus one smoke usage, in `MacAppState.refresh()`
     (a `sync` category debug line).
3. **Perf harness**: `scripts/heirloom-perf/`.
   - `profile.sh [name] [seconds]`:
     - Quits Heirloom, then `open -a /Applications/Heirloom-macOS.app`.
     - Waits for the pid, then runs `xcrun xctrace record --template 'Time Profiler' --instrument Hangs --instrument os_signpost --time-limit ${seconds:-120}s --attach <pid> --output /tmp/heirloom-perf/<name>-<timestamp>.trace`.
     - Must not use `--launch`: an app launched by xctrace isn't registered with LaunchServices, so
       accessibility/computer-use can't see its windows.
   - `summarize.py <trace>`:
     - Exports the `potential-hangs`, `time-profile` and `os-signpost` tables via `xcrun xctrace export`.
     - Resolves the id/ref deduplication.
     - Prints a Markdown summary:
       - hang count, total duration and worst hang;
       - top 20 main-thread inclusive frames owned by Heirloom/PhotosCore;
       - signpost interval stats (count/p50/p95/max per name).
   - Base the parser on the approach used in `04-baseline-profile.md`: the verifier's parsing scripts may
     still exist in `/private/tmp/claude-501/heirloom-traces/`. Reuse them if present; otherwise write
     from scratch.
   - Add `scripts/heirloom-perf/README.md` explaining the scripted manual scenario (see WP7 §3).

4. **UI-test wiring**
   - In `project.yml`, add the `Heirloom-macOS-UITests` target to the `Heirloom-macOS` scheme's test
     action, and regenerate.
   - Add `make test-macos-ui`, which runs `xcodebuild test -scheme Heirloom-macOS -destination 'platform=macOS' -only-testing:Heirloom-macOS-UITests`,
     with the same derived-data and module-cache flags as `build-macos`.
   - Add `make test-core`, which runs `swift test --package-path native-apple/PhotosCore`.
   - Make sure the existing `MacSmokeTests` pass. If any fail on the checkpoint commit, record them as
     pre-existing; don't fix app code here.
5. **Large synthetic fixture** (`FixtureSeed.swift`; WP4 takes ownership of this file after wave 1):
   - Support `--fixture-seed-count=<N>`, with N up to 150000. It generates N synthetic assets with
     realistic `localDateTime` spread over 15 years, a mix of photo, video (with duration), live photo
     and screenshot, varied aspect ratios, and a valid tiny thumbhash (reuse a few real thumbhash
     strings).
   - It goes through the same `apply()` path. The media pipeline runs in offline mode, so there's no
     network and cells show placeholders.
   - This enables automated perf runs without the owner's server. Document it in
     `scripts/heirloom-perf/README.md`.

## Acceptance
- The Release build and install work. The bundle has no debug dylib, and the team id is unchanged.
- `swift test --package-path native-apple/PhotosCore` passes.
- `profile.sh smoke 20` produces a trace, and `summarize.py` prints a summary without crashing.
- `make test-macos-ui` runs (record the pass/fail state).
- `--fixture-seed-count=100000` launches and shows the grid (it may be slow before WP2/WP3: record the
  launch time as a second baseline).
- Report: `reports/WP0-REPORT.md`, including the exact test commands.
