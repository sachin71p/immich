## Step 2 — Change notifications (new `MacAssetChangeCenter.swift`)
```swift
enum MacAssetChange: Sendable {
  case favorite(ids: Set<String>, isFavorite: Bool)
  case removedFromCurrentContexts(ids: Set<String>)   // trash, lock, hide, archive, move out of a library
  case edited(ids: Set<String>)                        // rotation/edit saved → thumbnails must refresh
  case albumsChanged                                   // membership changed; only matters for Not-in-Album filter / album pages
}
@MainActor final class MacAssetChangeCenter { static let shared; func post(_:); func changes() -> AsyncStream<MacAssetChange> }
```
Every mutation site in the owned files posts through it:
- `toggleFavorite`, `trash`, move `onDone`, add-to-album `onDone`, lock/hide if present.
- WP4 and WP5 will post from their files.

## Step 3 — Loader (`MacGridLoader.swift`)
Replace the class body with:
```swift
@MainActor @Observable final class MacGridLoader {
  enum Phase: Equatable { case idle, loading, loaded, failed(String) }
  private(set) var snapshot: TimelineGridSnapshot = .empty   // class → identity comparison, O(1)
  private(set) var phase: Phase = .idle
  private(set) var lastPatch: (revision: Int, indexes: [Int]) = (0, [])
  @ObservationIgnored private var source: [TimelineSourceSection] = []
  @ObservationIgnored private var presentation = Presentation()  // order, include predicate inputs
  @ObservationIgnored private var loadTask: Task<Void, Never>?
  @ObservationIgnored private var rebuildTask: Task<Void, Never>?
  @ObservationIgnored private var generation = 0
  func load(store:userId:destination:grouping:switcher:)   // see rules
  func setPresentation(order:filters:userId:albumMemberIds:) // rebuild only
  func apply(_ change: MacAssetChange, destination: SidebarDestination)
}
```
Rules:
- **No `assetsById`.** No `[TimelineRow]`, `[MacGridSection]` or dictionaries as observable stored
  properties. Delete `MacGridSection` once it has no users.
- `load`:
  - Cancel `loadTask` and start a new one.
  - Fetch with the WP1 single-transaction row queries. They're already async off-main; don't wrap store
    calls in `MainActor` work.
  - Build `[TimelineSourceSection]`:
    - All Photos → one `.none` section.
    - Months → `.month` sections titled with `TimelineBucketTitle`.
    - Years → for each year, an empty `.year` section followed by that year's `.month` sections.
  - Then call `TimelineGridSnapshot.build` in `Task.detached(priority: .userInitiated)`, and assign it
    only if the task wasn't cancelled and its generation is still current.
  - `.album(id)`: use the WP1 row query (`albumAssets`), not `store.assets(ids:)`.
  - `.camera`, `.hidden`, `.archive`: map to rows off-main.
- **Cancellation is not an error.** Catch `CancellationError` (and `URLError.cancelled`), return
  silently, and keep the current snapshot. Other errors: `phase = .failed(message)`, log via
  `HeirloomLog.timeline`, and keep the old snapshot if the destination didn't change.
- Destination changed: set `snapshot = .empty` immediately so old content never shows under a new title.
  The view shows a spinner only if loading takes > 150 ms.
- Grouping or library-switcher changed in the same destination: keep the old snapshot until the new one
  is ready.
- `setPresentation`: build the include predicate as a `@Sendable` closure capturing value copies:
  - `filters: Set<TimelineQuickFilter>`, `userId`, `albumMemberIds: Set<String>?`;
  - `.edited` uses `row.isEdited`; `.capturedByMe` uses `row.ownerId == userId`;
  - `.notInAlbum` uses `!albumMemberIds.contains(row.id)`.

  Then rebuild off-main (cancel any previous rebuild). **No main-thread pass over rows.**
- `apply(change)`:
  - favorite → `snapshot.patching`. Set `lastPatch` to the changed indexes, or, in the Favorites
    destination when unfavoriting, `removing`.
  - removed → `removing`, which bumps the generation.
  - edited → bump `lastPatch` with those indexes so cells reload images. Also evict memory-cache
    entries for those ids (`pipeline.memory`), and drop disk-cache entries with the `edited` flag as
    appropriate.
  - albumsChanged → if the `.notInAlbum` filter is active, refetch `store.assetIdsInAnyAlbum` and rebuild.
  - The loader subscribes to `MacAssetChangeCenter` in a task owned by the view (see Step 4).

## Step 4 — Main window (`MacMainWindow.swift`)
- Delete these and read the snapshot instead:
  - `displayedSections`, `displayedRowIds`, `libraryDateRange`, `matchesQuickFilter`;
  - the footer's `flatMap`/`filter`;
  - `dateString` per row: use `snapshot.dayKeys`;
  - the `albumAssetIds` per-album loop.
- Snapshot values to read:
  - footer: `snapshot.photoCount` / `videoCount`;
  - subtitle: `snapshot.dateRange`, formatted with the existing static formatter;
  - viewer context.
- `albumAssetIds`: fetch via `store.assetIdsInAnyAlbum(userId:)` **only when** `.notInAlbum` is in
  `quickFilters`; otherwise pass `nil`.
- `.onChange(of: timelineOrder)`, `.onChange(of: quickFilters)` → `loader.setPresentation(...)`.
- `reloadKey`: destination id + grouping + switcher + `state.timelineVersion`. Remove
  `state.spaces.count` and `state.albums.count` from the key; they caused full reloads after every
  refresh.
  - Add `var timelineVersion = 0` to `MacAppState`, incremented when a sync run completes and applied
    changes. Look at `SyncCoordinator`'s result, or bump after each successful `syncNow`/background sync
    if no change count is available, and document which.
  - A sync-triggered reload keeps the old snapshot until the new one is ready (same destination).
- Extract the grid subtree into `struct MacTimelineGridPane: View`. It takes `loader`, `pipeline`,
  `exporter`, `itemSize`, `usesSquareThumbnails`, the `isSelecting` binding, the selection binding and
  callbacks. Toasts, hover, sync status and other state then don't re-evaluate the grid.
  `MacLibraryBrowser.body` must not touch `loader.snapshot.rows`.
- Mutations: remove `await reload()` from `toggleFavorite`/`trash`/move/add-to-album.
  - Post a `MacAssetChange` on success.
  - `toggleFavorite` reads the current state from `snapshot.rows[snapshot.indexById[id]]`; no store fetch.
- Viewer context: change `MacAppState.viewerContext` from `[String]` to
  `viewerContext: TimelineGridSnapshot?` (display order).
  - `openViewer` and New Viewer Window set it to `loader.snapshot`.
  - In `MacViewer.swift`, make the minimal compile fix: find the index via `indexById`, then clamp
    (WP5 does the full viewer work). This fixes U7.
- Error banner (U3): show `loader.phase == .failed` as a compact inline banner with a **Retry** button.
  Never show cancellation. Remove the old `loader.error` red text.
- Selection model: `selectionModel.retarget(to: loader.allRowIds)` becomes a retarget that keeps only
  ids present in `snapshot.indexById`. That's O(selected), not O(rows).

## Step 5 — Interim grid adaptation (`MacCollectionGridView.swift`, `MacGridCell.swift`)
WP3 rewrites these later, but this step must fix the blank-grid bug now.
- New inputs: `snapshot: TimelineGridSnapshot`, `lastPatch`, `pipeline`, `exporter`, `itemSize`,
  `usesSquareThumbnails`, `isSelectionMode`, selection binding, and callbacks.
  - Remove `sections`, `assetsById` and `rowDates`.
- `updateNSView`:
  - `snapshot.generation != coordinator.generation` → `reloadData()`;
  - otherwise, `lastPatch.revision` changed → `reloadItems(at:)` for those indexes (section 0 in the
    interim single-section flow layout).
  - Selection sync diffs against the coordinator's last-applied `Set<String>` through `indexById`.
- `sizeForItemAt` uses `snapshot.rows[i].aspectRatio`, with no dictionary lookup.
- Cell load uses `pipeline.stream(id:thumbhash:tier:)` from the row. Before starting the task:
  - use `pipeline.cachedImage` synchronously if present;
  - else use `pipeline.cachedPlaceholder`.

  This fixes the permanently blank cells (R1).
- **Border fix now** (R10 minimal): in `prepareForReuse`, set `borderColor = NSColor.clear.cgColor`, not
  `nil`. WP3 redoes the cell properly.
- Drag export needs `Asset` for `originalFileName`: fetch `store.assets(ids:)` in
  `draggingSession(willBeginAt:)` into the drag state (a fileName map).
  `namesOfPromisedFilesDroppedAtDestination` reads that map, with a bounded synchronous fallback as today.
- `showPreview` / Quick Look: fetch the asset by id (the existing code already falls back to the store).
