## Deviations
1. `SharedSpaceRepository`/`AssetRelocationService` aren't in `BASE_SERVICE_DEPENDENCIES`; no BaseService subclass
   in this codebase overrides its constructor (all rely on the inherited one), and `test/utils.ts`'s `newTestService`
   is typed to `BaseServiceArgs` exactly, so appending constructor params would break every existing caller.
   Resolved via `@Inject()` property injection on `UserService` instead (both are already app-wide providers);
   unit tests attach mocks with `Object.assign(sut, {...})` after `newTestService(UserService)`. Marked with
   `// fork: shared-libraries` explaining why.
2. Bug found+fixed in already-implemented task 5 (`asset-media.service.ts` `uploadAsset`): an explicit non-member
   `spaceId` silently fell back to personal instead of the 403 the S4 brief's own test list requires; now throws
   `ForbiddenException` for an explicit non-member target, while a stale *preference*-derived target still falls
   back silently (per DECISIONS §9).
3. Bug found+fixed: `asset-media.service.spec.ts` never mocked `userRepository.getMetadata`, so 6 pre-existing
   upload tests threw once task 5's preference lookup ran; added a default `mocks.user.getMetadata.mockResolvedValue([])`.
4. Bug found+fixed: `Library` type in `database.ts` was missing `uploadPath` (real column, already used elsewhere),
   blocking `pnpm run check` for new move tests targeting a library.
