# A2 handoff — Core: image pipeline & cache tiers

## Summary
All 5 brief tasks implemented in `native-apple/PhotosCore/Sources/Media/`: `MediaEndpoint`
(thumbnail `size=thumbnail`/preview/fullsize/original, video playback, live-photo motion via
`livePhotoVideoId`, `edited=true` variants); Nuke-backed `MediaPipeline` (thumbhash
placeholder → cached tier → network tiers via `AsyncThrowingStream`, Resize downsampling in
pixel units, visible `.high` / prefetch `.veryLow` priorities, cancellation, `prefetch(ids,tier)`);
`TieredMediaCache` actor (per-tier budgets + LRU, pins never evicted, `setBudget`/`evict`/`usage()`
for A6); offline serves best cached tier else `unavailableOffline`; `ThumbHash` pure-Swift decoder
byte-identical to `server/node_modules/thumbhash` on 4 golden vectors; `MediaFormatInfo`
(HEIC/RAW/video classification, EXIF-profile HDR flag, verbatim original bytes).
`swift build` + `swift test --disable-sandbox`: 55/55 pass (29 A0/A1 + 26 new `[A2-*]`).

## Deviations
- Media URLs are built as paths, not via generated `Operations`: Nuke needs plain URLs, and
  `viewAsset`/`downloadAsset`/`playAssetVideo` were deliberately NOT added to the OpenAPI filter
  (keeps generated client small; no typed call site needs them yet).
- Disk tiers are a custom actor, not Nuke `DataCache`: per-tier budgets + cross-tier LRU + pins
  need custom logic; Nuke still owns memory cache, coalescing, priorities, prefetch, decode.
- Offline disk hits decode via ImageIO thumbnailing (orientation-correct, downsampled), not Nuke
  file-URL loads — fewer behavioural unknowns, same bytes.
- `swift test` needed `--disable-sandbox` (SwiftPM's inner sandbox conflicts with the agent
  sandbox; session sandbox stayed on). `verify.sh core` unmodified and unrunnable here for that
  reason alone — rerun on host expects green.

## Open issues
- No `SharedLibrary`/spec signal for ProRAW: all DNG classified RAW; revisit if server adds a flag.
- ThumbHash base64url tolerance is lenient by design (normalises `-_` + padding); strict Immich
  format is standard base64 — no action unless server ever emits url-safe form.
- A5/A8 will bind `MediaLoadedImage.dynamicRange` to the platform HDR view path and supply grid
  `targetPixelSize`s; defaults (512/2048/full) are in `MediaTier`.
