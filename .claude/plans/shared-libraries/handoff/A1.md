## CODEMAP-FIX / deviations
- `open-api/immich-openapi-specs.json` is stale vs `server/src/enum.ts` (S6 handoff admitted regeneration
  didn't run): `SyncRequestType`/`LibraryResponseDto` lack fork additions. Worked around with a hand-written
  `SyncRequestTypes` string list and by not depending on `library.uploadPath` (below).
- `/sync/stream`'s response has no `content` in the spec (`@Res()` bypasses Nest DTO serialization, like
  upstream mobile's own client); `SyncStreamClient` uses `URLSession.bytes(for:)` directly, reusing the
  connection's token/serverURL — the only endpoint not called through the generated `Operations`.
- Libraries/Shared-spaces reuse identical operationIds (`getMembers`/`addMembers`/`updateMyTimeline`/
  `removeMember`); generator validates uniqueness post-filter so both can't be selected together — only
  shared-spaces wired (via `filter.paths`).
- No `SharedLibraryMemberV1` sync entity exists; `library_members` stays schema-only; `accessibleLibraryIds`
  is derived from "received a `SharedLibraryV1` row" (stream is membership-scoped) instead.
- `library.uploadPath` isn't exposed by any generated operation (checked directly); `MoveTargets` never
  offers a library target until a future spec regen exposes it — same observable result as "unknown".
- AP-02 vs `rules-cases.json` deferred to T0 (doesn't exist yet); `RulesTests.swift` encodes DECISIONS
  §4/§6/§10 directly, to be reconciled against T0's fixture later.
- No websocket trigger (brief: optional); triggers are foreground/pull-to-refresh + a timer loop.
