# Testing Plan — regression suite for the fork

Goal: every requirement (R1–R17), invariant (I1–I7) and lifecycle rule in `DECISIONS.md` has automated tests
that run locally during development and after every upstream merge, using real image files placed in personal,
shared, and external libraries of several users, and asserting real on-disk file locations.

Agents: read §1, §8 and only the matrix rows (§5) whose Phase column names your phase.

## §1 Test tiers
| Tier | Tool | Needs | Location (new files only → no upstream conflicts) | Runs in |
|---|---|---|---|---|
| U unit | vitest (server), vitest (web), Swift Testing (Apple core) | nothing | next to code, as upstream does | seconds, anywhere (agent sandbox OK) |
| M medium | server vitest medium (testcontainers Postgres + real temp FS) | Docker | `server/test/medium/specs/fork/` | ~minutes, host with Docker |
| E e2e API | e2e vitest against docker-compose stack | Docker | `e2e/src/specs/server/api/fork/` | ~5–10 min |
| W e2e web | Playwright against the same stack | Docker + browsers | `e2e/src/specs/web/fork/` | ~5–10 min |
| A Apple | `swift test` (core, fixture-driven) + few XCUITests (optional live stack) | Xcode | `native-apple/PhotosCore/Tests/`, `native-apple/Apps/*/UITests/` | host with Xcode |
| G upgrade gate | scripts (migration from upstream DB, OpenAPI diff) | Docker | `scripts/fork-test/` | before/after upstream merges |

Naming rule (enforced by the coverage check, §6): every fork test title starts with its case id in brackets,
e.g. `it('[R6-02] contributor favorite is visible to owner', …)`. One test may carry several ids.

## §2 Fixtures (three sources, one manifest)
All fixtures are described in `e2e/fork-assets/manifest.json` — the single source of truth for expected metadata.
Tests look up expectations from the manifest; they never hard-code EXIF values.

1. **Synthetic (committed, deterministic)** — `e2e/fork-assets/generated/`, produced by
   `server/test/fork-fixtures/generate.ts` (runs in the server workspace so it can use the server's existing
   `sharp` + `exiftool-vendored` — no new dependencies). A seeded PRNG creates unique pixels per fixture (unique
   checksums), then EXIF/XMP is written. ~30 files, each < 150 KB. Regenerate only when the manifest spec
   changes; the generator verifies output matches the manifest (read back with exiftool).
   Coverage the set must provide:
   - dates across ≥3 years and ≥4 months (timeline buckets), one with timezone offset, one without EXIF date;
   - GPS at 3 distinct well-known cities + 5 without GPS (map, places, `hasLocation`);
   - 3 camera make/model/lens combos; ISO {100, 800, 3200}; fNumber {1.8, 4, 11}; focal {24, 50, 200};
     exposure {1/1000, 1/60, 2}; rating {0, 3, 5}; orientation {1, 6}; description text;
   - dimensions: small (640×480) and large (4000×3000); formats jpg, png, webp; one 2:1 equirectangular with
     `ProjectionType=equirectangular` (360°);
   - 3 files with `.xmp` sidecars (one sidecar overriding the date, one adding a keyword);
   - one exact-duplicate pair (same bytes) for duplicate-in-target tests;
   - one file carrying unusual tags (MakerNotes-like custom XMP namespace, a binary thumbnail) for R12 stripping.
2. **Upstream `e2e/test-assets` submodule** (licensed by Immich): real HEIC, RAW/DNG, videos, motion photos.
   T0 initializes it (`git submodule update --init e2e/test-assets`) and records the chosen files in the manifest
   (kind `upstream`, path relative to the submodule).
3. **Personal (optional, never committed)** — `e2e/fork-assets/personal/` is gitignored. Tests needing them are
   tagged `@personal` and skip with a visible notice when a file is absent. Expected file names (user supplies):
   `live.heic` + `live.mov` (iPhone Live Photo pair), `portrait.heic` (Portrait mode with depth), `proraw.dng`,
   `hdr.heic`, `pano.jpg`, `cinematic.mov`, `video-hevc.mov`, `screenshot.png`, `burst-1.heic`…`burst-3.heic`.
   `e2e/fork-assets/personal/manifest.local.json` (gitignored) is generated by `scripts/fork-test/index-personal.ts`
   (reads EXIF, records checksums) so tests have expectations without committing anything.

## §3 The "world" (deterministic seed used by E, W, A-recording)
Builder: `e2e/src/specs/server/api/fork/world.ts` → `buildWorld(opts)` returns ids for everything; idempotent
after `utils.resetDatabase()`. Composition:
- Users: `admin`, `alice`, `bob`, `carol` (outsider), `dave` (alice's partner, inTimeline=true).
- Spaces: `Family Mobile` (owner alice, contributor bob), `Camera` (owner bob, contributor alice),
  `Carol Solo` (owner carol).
- External libraries (import paths under `/test-assets/temp/fork/…`, host `e2e/test-assets/temp/fork/…`):
  `Archive` (owner alice, member bob, `uploadPath` = `<import>/incoming`), `NAS-RO` (owner admin, member carol,
  no uploadPath).
- Albums: `Trip` (owner alice, bob as **viewer**) containing alice-personal + Family Mobile assets.
- Assets (by manifest id): each container gets ≥3 synthetic fixtures incl. at least one with sidecar, one with GPS;
  a live-photo pair (upstream or personal) in alice personal; a 2-asset stack in bob personal; one Locked asset in
  alice personal; the duplicate pair split between bob personal and Camera.
- Preferences: bob `defaultUploadTarget = Family Mobile`; alice default personal.
- Variants: `buildWorld({ storageTemplate: 'on' | 'off' })` — R17 cases run in both.
Media location: the fork compose override sets `IMMICH_MEDIA_LOCATION=/fork-data` and bind-mounts it to
`e2e/.fork-data/` so tests can check real files on the host (see T0). Container `/fork-data/…` maps 1:1 to the
host mirror (`toHostPath` in `fork/disk.ts`, rooted at the exported `containerMediaRoot`). Two consequences:
- Template-OFF originals carry the server's stored basename (`<upload-uuid>.<ext>`), not the client filename —
  oracles must derive nesting from `basename(originalPath)` (see §4). Template-ON originals keep display names.
- Any spec hardcoding `/data/…` container paths (upstream `integrity.e2e-spec`) is invalid on the fork stack —
  it plants/scans a tree the server never writes. Those specs run only via the `upstream` tier (§6, §8).
`uploadFixture` also uploads each fixture's `<file>.xmp` sidecar when present, so sidecar assertions hold.

## §4 Test helpers (fork-only files)
- `fork/disk.ts` — `expectFilesAt(asset, { template, … })`: an **independent** re-implementation of DECISIONS §7
  (do not import server code — the point is to catch server regressions). It asserts original, sidecar, thumbnail,
  preview, fullsize, encoded video exist at expected host paths and old paths are gone. Template-OFF originals are
  asserted exactly via `expectedUploadPath(storageKey, basename(originalPath))` — never from `originalFileName`.
  Sidecars live at `<originalPath>.xmp` (server migrates them with the original in both modes).
  `auditDisk()` walks `e2e/.fork-data/{library,upload,thumbs,encoded-video}` and the DB (via API/admin query) and
  reports orphans and missing files.
- `fork/jobs.ts` — `settle()`: wait for all queues (storage template/relocation, thumbnails, metadata, library)
  and `asset_relocation` empty; `pauseRelocation()/resumeRelocation()` via jobs API (for I6 cases).
- `fork/sync.ts` — read `/sync/stream` JSON-lines into typed events; `ackAll()`.
- `fork/as.ts` — per-user SDK clients (`as(alice).moveAssets(...)`), status assertions (`expect403`).
- `fork/record-sync.ts` — records sync streams for each world user into
  `native-apple/PhotosCore/Tests/Fixtures/world/*.jsonl` (A-tier fixtures stay in lockstep with the server).
- `e2e/fork-assets/rules-cases.json` — table of permission/move/scope cases (actor, asset container, action,
  expected). Consumed by server unit tests AND Swift `Rules` tests → guaranteed parity between server and apps.

## §6 Runner & commands (single entry point)
`scripts/fork-test/run.sh <tier…>` (new file; wraps existing commands):
- `unit` → server `pnpm run test`, web `pnpm run test --run`, fork unit specs only via `--grep '\[(R|I|MV|LC|SY|INV|AP)'` option.
- `medium` → `cd server && pnpm run test:medium -- test/medium/specs/fork` (Docker).
- `e2e-api` → ensure submodule + fixtures; `docker compose -f e2e/docker-compose.yml -f e2e/docker-compose.fork.yml up -d --build`;
  wait healthy; `cd e2e && VITEST_DISABLE_DOCKER_SETUP=true pnpm test -- src/specs/server/api/fork`.
- `e2e-web` → same stack; `cd e2e && pnpm test:web -- src/specs/web/fork`.
- `apple` → `native-apple/scripts/verify.sh core` (+ `ios`/`mac` when requested).
- `upstream` → upstream e2e API + web + medium suites (INV-03), always on the DEFAULT compose stack
  (no fork override): upstream specs hardcode `/data/…` container paths and are invalid under `/fork-data`.
- `upgrade` → UP-01 + INV-02 scripts.
- `coverage` → greps all fork specs for `[ID]` tags and diffs against §5; fails if a case owned by a completed
  phase (per STATUS.md ✅) has no test.
- `all` → unit, medium, e2e-api, e2e-web, upstream, coverage (apple when Xcode is healthy).
- Flags: `--keep-stack` (don't tear down), `--template on|off|both` (default both for R17 cases),
  `--personal` (require personal fixtures; default: skip if absent).
Output: `e2e/.fork-report/<timestamp>.md` — per tier pass/fail/skip counts and failing case ids.

## §7 Regression gate
- During development: implementer runs `unit` (+ `medium` when Docker exists); verifier runs the phase's tiers.
- Before committing a phase that touches server behaviour: `run.sh unit medium e2e-api coverage`.
- After every upstream merge (FORK.md procedure): `run.sh all upgrade`; merge is not accepted with any failing
  fork case or INV-02/INV-03 failure.
- CI: `.github/workflows/fork-tests.yml` (new file) runs `unit`, `medium`, `e2e-api`, `e2e-web`, `coverage` on
  pushes to `feat/**` and `main` of the fork.

## §8 Where tests can run (important for agents)
- The agent sandbox blocks sockets and has no Docker, so M/E/W/G tiers cannot run there. Verifiers must either
  run those tiers with the sandbox disabled on a host with Docker Desktop running, or report the tier as
  **NOT RUN** — never PASS. The orchestrator must not mark a phase ✅ with server-behaviour tiers NOT RUN; mark it
  🟨 "awaiting host run" and ask the user to run `scripts/fork-test/run.sh <tiers>`.
- Container/host path split: the fork stack (`+ docker-compose.fork.yml`) serves `/fork-data`; the default stack
  serves `/data`. Never run upstream path-planting specs (notably `integrity.e2e-spec`, which `docker exec`s files
  into `/data/upload/…`) on the fork stack — every detection reads zero. Fork-oracle specs run on the fork stack.
- Apple tier needs a healthy Xcode toolchain on the host (A0 reported an SDK/compiler mismatch — fix before A1).
- Upstream server medium specs have two host prerequisites (both provided by mise — never run them with bare
  `pnpm`, which silently uses the wrong toolchain): (1) `mise run //:plugins` must have built
  `packages/plugin-core/dist/plugin.wasm` first, otherwise the workflow core-plugin spec fails with N cryptic
  `Plugin method not found` errors (the import WARN swallows the underlying ENOENT); (2) `ffprobe` must be the
  pinned `github:jellyfin/jellyfin-ffmpeg 7.1.3-6` from the root `mise.toml`/`mise.lock` (it is a bare-PATH lookup
  in `media.repository.ts`) — a newer host ffmpeg (e.g. Homebrew 9.x) shifts keyframe packet timings and breaks
  the `audio-video` golden expectations in `server/test/fixtures/media.stub.ts`, which must not be edited to
  match local drift.
